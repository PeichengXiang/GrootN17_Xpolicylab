# Spark0 joint54 compatibility result

Status: **blocked by the official XPolicyLab GR00T N1.7 adapter ABI**.

The six Spark0 tasks expose the same joint-space layout for both state and
action:

```
left_arm(7) + left_hand(20) + right_arm(7) + right_hand(20) = 54
```

The unmodified XPolicyLab `policy/GR00T_N17/model.py` instead packs and
unpacks two `arm(6) + gripper(1)` groups, for a total of 14 values. Its
official `process_data.sh` also accepts only the `arx_x5` modality contract.

Converting Spark0 to that 14D layout would discard all dexterous-hand control
and would mislabel the seventh arm joint as a scalar gripper. That is not a
format conversion; it changes the task semantics. No GR00T dataset or training
job is therefore generated by this repository.

Run the executable audit to re-check the source and adapter contracts:

```bash
/personal/miniconda3/envs/xpolicylab/bin/python \
  scripts/check_groot_joint54_compatibility.py
```

The safe ways to unblock this are either:

1. an official XPolicyLab GR00T N1.7 joint54 adapter/config, or
2. explicit authorization to change the XPolicyLab model adapter and data
   modality code.

Neither is a data-only change, so both are outside the present constraint.
